# 05 · What does a voice that launches further sound like?

The revised short actually edits a voice, measures each edited sound with librosa pYIN, turns that pitch into a rail, and compares where the cart lands. Original and selected audio are played separately from narration.

```sh
python -m pip install -r requirements.txt
python launch_experiment.py --render
# Or supply your own authorized pitched recording (roughly 1–2 seconds):
python launch_experiment.py --source my-voice.wav --render
```

Outputs in `launch-output/`: original/optimized WAV, original/optimized MP4, and `metrics.json` containing every measured pitch contour, candidate result, geometry and launch state. FFmpeg is required for `--render`. Without a supplied recording, the script creates an explicitly synthetic harmonic vowel; this is not George and does not reproduce the video's exact numbers.

The video uses an authorized local George word sample, which is not redistributed here. Its six tested ending pitch changes were 0, 6, 12, 18, 24 and 30 semitones. Pitch shifts increase progressively across the word, with overlapping windows and weighted crossfades. Every edited waveform is measured again; the chosen candidate is the best of this finite list, **not** a globally optimal sound. The original travelled 1.3756 m beyond the rail end; the selected 30-semitone-ending candidate travelled 10.4946 m. These are simulation units interpreted as metres, not physical safety predictions.

The same pitch-to-height mapping, 8 m rail, initial speed 8 m/s, gravity 9.81 m/s² and friction coefficient .015 apply to every candidate. The cart is constrained to the rail until its open end. A smoothed straight fit to the last portion defines the release slope. Height and slope both change with the sound; it is not an angle-only comparison. Speed follows gravitational energy minus approximate friction, then a ballistic trajectory reaches the same ground plane. Audio is an input to geometry, not a force propelling the cart. This is a stylized educational point-cart model, not a real ride design or a contact-loss solver.

`run.py`, `render.py`, `physics.py`, `extract_pitch.py` and `assets/published-pitch.json` retain the earlier crest/contact experiment for reproducibility. Use **launch_experiment.py** for this new version. No hosted narration service, API key or GPU is needed.
