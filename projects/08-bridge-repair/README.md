# Bridge repair / 무너진 다리에 새 하중 경로를 만들면

An authored NumPy axial spring network receives a fixed downward load. Members break when computed axial force exceeds35000 simulation units. The baseline breaks **9 members**. The algorithm finds the most deflected deck node just before the first failure, tests adding two and four support members, and selects the smallest tested repair with **0 broken members**. Load30000 and failure threshold remain unchanged. The displayed block marks load application; it is not a separately simulated falling block.

`run.py` writes `metrics.json`, `simulations.json` (baseline and both repair trials) and a12second labeled `preview.mp4`. It uses a1/600second semi-implicit Euler step and records30fps. `clean_results.py` reruns the same baseline and selected two-member repair for10seconds and writes `clean-failure.mp4`, `clean-result.mp4`, and matching `*-trajectory.json`, as used in the latest Short. The overview pauses at a diagnostic state; clean clips run at1x.

Change load, spring constants, fracture threshold or repair connections in `run.py`. The clean renderer's repair level/node are explicit and must be updated if a new result is selected. This is a simplified2D axial mass-spring illustration, not engineering design software. It does not model continuum stress, bending, buckling, plasticity or realistic fracture mechanics, and its units are arbitrary.

## Run locally

Python 3.12 recommended. Install FFmpeg and make `ffmpeg` available on PATH (macOS: `brew install ffmpeg`; Ubuntu: `sudo apt install ffmpeg`; Windows: install FFmpeg and add its bin directory to PATH).

From this project directory:

```sh
python -m venv .venv
# macOS/Linux:
source .venv/bin/activate
# Windows PowerShell instead: .venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python run.py
python clean_results.py
```

No API key, account, GPU, network service, or downloaded model is required after dependency installation. Generated MP4 files are silent experiment renders, not the narrated promotional Short. Renderers draw recorded simulation states with Pillow and encode H.264 using FFmpeg. Any labels use Pillow's bundled font, with no system font dependency. Floating point results can vary slightly by platform.

## Provenance and dependencies

Authored simulation and renderer code from the corresponding Siljangnim Shorts experiment. `provenance.json` records original source hashes and packaging changes. Recorded JSON is supplied for inspection and can be regenerated by the commands above.

Dependencies: NumPy (BSD-3-Clause), Pillow (HPND). FFmpeg is an external executable with LGPL/GPL terms depending on its build; its binary is not included. Dependency source and licenses remain with their upstream distributions.
